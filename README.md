# 数独ソルバー

Python 3.10 以上。テキスト入力は標準ライブラリのみ、画像入力は OpenCV と numpy を使う（`pip install -r requirements.txt`）。

```
python sudoku_image.py 問題.png                   # 画像を読み取って解く（結果はテキスト表示のみ。-o 解答.png で画像も保存）
python sudoku_solver.py puzzles/easy.txt          # 解く
python sudoku_solver.py --check puzzles/hard.txt  # 解く＋解の一意性を確認
python -m unittest test_sudoku_solver test_sudoku_image  # テスト
```

ライブラリとしては `parse(text) -> list[int]` と `solve(grid, max_solutions=1) -> Result` を使う。

## Web版（スマホのカメラで解く）

`docs/` はスマホのブラウザで開くWebページ。「カメラで撮影」で撮った写真をその場で読み取り、解答を表示する（黒=問題の数字、青=答え）。写真はブラウザの中だけで処理し、どこにも送信・保存しない。読み取りを誤ったときは、マスをタップして直してから解き直せる。写真を使わず手で入力することもできる。「カメラで撮影」はスマホ専用（PCのブラウザはこの撮影の仕組みに対応しておらず、ファイル選択になる）。PCでは「写真を選ぶ」で画像ファイルを読み込める。

Android では「カメラで撮影」を押すと、カメラアプリを起動せず、ページの中にカメラの映像を出して撮る。カメラアプリを起動している間に Chrome がメモリ不足で強制終了され、戻ったときに「メモリ不足のため前の操作を完了できませんでした」と出て写真が届かないことがあるため。最初はカメラの使用許可を求められる。許可しなかったときなど、ページ内でカメラを使えないときはカメラアプリで撮る。iPhone と PC はこの問題が起きないため、これまでどおり（iPhone はカメラアプリ、PC はファイル選択）。

解けたあと「解き方を見る」を押すと、最初の盤面から1手ずつ、数字を置いたマスや消した候補を示す（「次へ」「前へ」で進む・戻る）。「解説」を押すと、手筋の名前と理由を文章と色で示す。まずシングル（ある行・列・ブロックでその数字が入りうるのが1か所だけ／そのマスの候補が1つだけ）を探し、なければ候補を消す手筋（ロックト・キャンディデート、ネイキッド／ヒドゥンのペア・トリプル、X-Wing、XY-Wing、ソードフィッシュ）を、やさしい順に探す。初めて候補を消す手から先は、空きマスに候補（入りうる数字）を小さく表示する。どの手筋でも次の1手が見つからない難問では、そう知らせたうえで「答えから1つ置く」で進める（理由は示せないので紫で区別する。`puzzles/hard.txt` では 67 手のうち 5 手）。

表示言語はブラウザの言語設定で決まる。第一言語が日本語なら日本語、それ以外は英語で表示する。ページ下部のリンクで切り替えられる（URL に `?lang=ja` / `?lang=en` を付けて開くのと同じで、選んだ言語は記憶しない）。

公開手順（GitHub Pages、最初に1回だけ）: リポジトリの Settings → Pages → Build and deployment で Source を「Deploy from a branch」、Branch を `main` / `/docs` にして Save。数分後に `https://mr2-gts.github.io/sudoku/` で開ける。

`docs/` のファイルを変えたら、公開（`main` へのマージ）の前に `python tools/stamp_web_versions.py` を実行する。ページが読み込むファイルの URL に、中身から決めた版（`app.js?v=1a2b3c4d`）を付け直すツール。GitHub Pages はブラウザにファイルを 10 分間キャッシュさせるが、それより長く古いファイルが使われることがあり、新旧が混ざるとモジュールの読み込みでエラーになってページの処理がまったく動かなくなる（実際にスマホで起きた。古い `solver.js` に、新しい `steps.js` が読み込む `PEERS` がなかった）。中身が変わったファイルは URL も変わるので、ブラウザは必ず新しいファイルを取りに行く。付け忘れは `node --test test_web_solver.mjs` で検出する。それでも処理が動かなかったときは、`docs/load-check.js` が理由とサイトのデータの消去方法を画面に表示する。

| ファイル | 役割 |
|---|---|
| `docs/index.html` `docs/style.css` | 画面 |
| `docs/app.js` | 画面の操作（写真の読み込み・ページ内カメラ → 読み取り → 解く → 表示、修正） |
| `docs/i18n.js` | 表示言語の判定と、日本語・英語の文言 |
| `docs/vision.js` | `sudoku_image.py` の読み取り処理の移植。OpenCV は使わず、必要な画像処理を自前で実装（ページが軽く、外部サービスに依存しない）。|
| `docs/solver.js` | `sudoku_solver.py` の移植 |
| `docs/steps.js` | 解き方の解説の手順（人の手筋で1手ずつ数字を置いたり候補を消したりする順番と、その理由）。Web 版だけの機能 |
| `docs/load-check.js` | ページの処理が動かなかったとき（古いファイルが残って新旧が混ざったときなど）に、理由と直し方を表示する |
| `docs/digit_model.bin.gz` | 見本データ（`digit_model.npz` を `tools/export_web_model.py` で変換したもの、約 810KB） |

大きな写真は長辺 1200 ピクセルに縮小してから読み取る（ページ内カメラは 1920 ピクセル程度の映像を求め、撮った1コマを同じように縮小する）。テスト画像 12 枚すべてで Python 版と同じく正しく読み取れることを確認した（1枚 0.5 秒前後、PC の Chromium）。`node --test test_web_solver.mjs` でソルバーと解説の手順のテストを実行できる。手元で試すときは `python -m http.server -d docs` などで配信して開く（ファイルを直接開くと見本データを読み込めない）。

## 入力形式

1〜9 は数字、空きは `0` か `.`。それ以外の文字（空白・改行・`|` `-` `+`）は無視するので、9行×9文字でも81文字1行でもよい。

## 設計

| 構成要素 | 役割 |
|---|---|
| データ表現 | 盤面は 81 要素の `list[int]`（0=空き）。内部では各マスの候補を 9bit のビットマスクで持つ（bit0=1 … bit8=9）。|
| 静的な表 | `UNITS`（行・列・ブロックの27グループ）と `PEERS`（各マスと同じグループの20マス）を起動時に1回だけ作る。|
| 制約伝播 `_assign` | マスを確定 → 周りの候補から消す → 候補が1つになったマスも連鎖して確定（naked single）。|
| 制約伝播 `_hidden_singles` | グループ内で数字を置ける場所が1か所なら確定（hidden single）。|
| 探索 `solve` | 伝播で埋まらなければ、候補が最少のマス（MRV）で仮置きし再帰。矛盾したらその分岐を捨てる。候補配列をコピーして試すので「元に戻す」処理が不要。|
| 一意性判定 | `max_solutions=2` で2つ目の解を探す。見つからなければ一意。|

矛盾は内部例外 `_Contradiction` で探索を巻き戻し、利用者向けの入力エラー（81マスでない、初期配置に重複）は `SudokuError` で返す。

目安: 難問（`puzzles/hard.txt`）でも 0.1 秒未満。

## 画像入力の設計（`sudoku_image.py`）

| 段階 | 処理 |
|---|---|
| 読み込み | グレースケールで読み込む（写真の向きは OpenCV が補正する）。長辺が 1200 ピクセルを超える写真は 1200 に縮小する（Web 版と同じ）。大きいまま処理すると、画面のモアレなどで2値化した盤面の外枠が途切れ、盤面を見つけられないことがあった。300 ピクセル未満の小さい画像は2倍に拡大する。|
| 盤面検出 | 適応的2値化（影に強い）→ いちばん大きい輪郭の凸包を盤面とみなし、4角形に近似できなければ凸包上の点から四隅を選ぶ（盤面の端が写真の縁に接している場合など）。見つからなければ画像全体を盤面とする（盤面だけを切り抜いたスクショ向け）。|
| 歪み補正 | 四隅から射影変換し、450x450 の正方形にする。斜めに撮った写真もここで真上から見た形になる。|
| マス分割 | 50x50 ずつ 81 マスに等分。中央付近にあり、背景よりはっきり濃い塊（明るさの差 45 以上）を数字の一部とみなし、まとめて1つの数字にする。濃さで判定するので、画面のモアレや紙のざらつきを数字と誤認しない。細い書体で数字が複数の塊に分かれても拾える。さらに、濃い塊とつながる薄い画素（濃い部分の 25% 以上の濃さ）まで数字の範囲を広げ、4 の細い斜め線のように2値化で消えやすい線を補う（数字か空きかの判定は濃い部分だけで行う）。塊がなければ空き。|
| 数字認識 | 数字を 28x28 に正規化し、見本データ `digit_model.npz`（19 フォント × 1〜9 × 変形 30 通りから、変形で別の数字と同じ形になった見本を除いたもの、5015 件）と比べる k 近傍法（k=5）。19 フォントのうち 4 つは、上側が平らな 3（「Ʒ」に近い形）を 5 と読み誤らないよう後から足した書体（Google Fonts の OFL の M PLUS 1p・M PLUS Rounded 1c・Lexend・Montserrat）。|
| 出力 | テキストで表示する。`-o` 指定時のみ解答画像（元の数字=黒、埋めた数字=青）を保存。問題や画像は保存しない。|
| 誤読時 | 数字が17個未満、解なし、解が複数のいずれかなら誤読とみなして解答を出さず、表示された読み取り結果を直してテキストファイルにし、`sudoku_solver.py` に渡せば解ける。|

見本データは `tools/make_digit_model.py` で作る。作り直しても元と同じ見本にはならない（書体や画像処理ライブラリの版で描画が変わる）ので、書体を加えるときは `--add` で今の見本に足す（詳しくはツールの説明を参照）。テスト画像 `puzzles/images/` はリポジトリに含めない（`.gitignore` で画像ファイルを除外）。合成画像は `tools/make_test_images.py` で作れる（見本に使っていないフォントで描き、写真版は傾き・遠近・影・ノイズ・ぼけを加える）。実際の写真は同じフォルダに置き、正解を `puzzles/<画像名の最初の _ より前>.txt` に書くとテスト対象になる。画像がなければ画像テストは飛ばされる。開発時は合成12枚に加え、実際の写真4枚（画面の写真・斜め・盤面の端が切れたもの・明るさムラ）でも正しく読み取れることを確認した（写真は保存していない）。

未対応（試していない）: 手書きの数字、メモ書き（小さな候補数字）が入った盤面、盤面の一部が写っていない写真。
